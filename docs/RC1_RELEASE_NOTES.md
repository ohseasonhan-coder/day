# RC1 릴리즈 노트 (내부 검수용)

> 외부 사용자 공지용이 아니라 **내부 검수/출시 판단용** 문서입니다.
> 대상 브랜치: `codex/refactor-local-ai-engine` · 기준 커밋: 보안 정리(`9e7ed5d`) 이후

## 1. RC1 핵심 요약
- 쌤워크(보육교사 문서 자동화)의 **출시 후보 1차(RC1)**.
- 이번 RC의 초점은 **새 기능이 아니라 출시 전 보안·개인정보 리스크 정리 + 최종 QA 준비**.
- 앱 구조는 그대로: **100% 로컬(브라우저 localStorage) 기반, 외부 서버 없음, 외부 LLM API 없음**, 문장 생성은 로컬 규칙 엔진.

## 2. 이번 RC에서 완료된 항목
- 마스터 계정 하드코딩 비밀번호 제거 및 안전 처리.
- 계정 비밀번호 평문 저장 제거 → salt + 해시 저장.
- 기존 평문 계정의 로그인 시 자동 해시 마이그레이션.
- 설정 화면에 공용 기기 사용 주의 안내 추가.
- 운영 빌드 소스맵 비활성화(원본 소스/개발 문자열 비노출).
- 보안 자동화 테스트 14건 추가, 전체 232건 통과 / CI 빌드 성공.
- RC 직전 QA(흐름·모바일 UI·용어·관리자 비노출)는 `docs/RELEASE_CANDIDATE_QA_REPORT.md`에 정리 완료.

## 3. 보안 수정 내역 (상세)
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 마스터 비밀번호 | 코드에 `master / saem2026!` 하드코딩 | 운영 시드는 비밀번호 없이 `mustSetPassword`만 → 최초 로그인 시 관리자가 직접 설정. 편의용 계정은 `NODE_ENV!=='production'`에서만 시드(운영 번들에서 제거됨) |
| 비밀번호 저장 | localStorage에 평문 `password` | Web Crypto SHA-256 + per-account salt: `{ passwordHash, passwordSalt, passwordVersion: 2 }`, 평문 미보관 |
| 기존 계정 | 평문 그대로 | 로그인 성공 시 해시로 자동 변환 후 평문 필드 제거 |
| 세션 저장 | password 제외 | password / passwordHash / passwordSalt 모두 제외 |
| 손상 데이터 | 깨질 수 있음 | `getAccounts()`에서 비정상 항목 필터, 로그인 방어 |
| 빌드 산출물 | 소스맵에 원본 노출 | 운영 소스맵 비활성화(`.env.production`) |

### 보안 문자열 검사 결과(운영 build 산출물)
- `saem2026` → **0건** (제거 확인)
- `dev-master` → **0건** (운영 빌드에서 dead-code 제거)
- `fallback 사유`, `legacy 엔진` → **0건** (사용자 노출 문구 없음)
- 소스맵(`*.map`) → **생성 안 됨**
- `qualityScore`, `modularDrafts`, `passwordHash` → 번들에 존재하나 **노출 아님**:
  - `qualityScore`/`modularDrafts`는 **로컬 AI 엔진 내부 속성명**(브라우저에서 실행되는 규칙 엔진 코드). 사용자 화면에 렌더되지 않으며, 사용자 페이지에는 토큰이 없음(`adminExposure.test.js`로 보장). 번들에서 제거하려면 엔진 코드 변경이 필요해 이번 범위(엔진 무변경)에서 의도적으로 유지.
  - `passwordHash`는 새 **보안 필드명**일 뿐 비밀값이 아님.

## 4. 개인정보 보호 구조
- 모든 기록/문서/계정은 **사용자 기기(localStorage)** 에 저장. 외부 서버 전송 없음.
- 구글 로그인은 **인증만** 사용, 데이터는 여전히 기기에 저장.
- 구글 드라이브 백업은 **사용자 본인 드라이브**에만 저장(켠 경우).
- 백업 번들은 비민감 `engineSettings`만 포함, 검수 데이터/fallback 로그/사용자 교정은 **제외**.
- 비밀번호는 평문이 아닌 salt+해시로 보관(세션엔 해시도 미포함).

## 5. 현재 알려진 한계
- **완전한 서버 인증 보안이 아님** — 로컬 단일 SHA-256 해시는 느린 KDF(bcrypt/PBKDF2)가 아니므로 오프라인 대입에 상대적으로 취약. 기기 물리 접근 시 localStorage 자체는 열람 가능.
- 기존 평문 계정은 **최초 로그인 전까지** 평문이 남아 있음(로그인 시 1회 전환). 서버가 없어 강제 일괄 전환은 미적용.
- 운영 마스터 최초 비밀번호는 "첫 입력값으로 설정" 방식 → **설치 직후 관리자가 먼저 설정**해야 선점 위험 없음.
- AI 엔진 내부 토큰(`qualityScore` 등)은 번들에 포함(사용자 비노출). 번들에서 완전히 제거하려면 관리자 컴포넌트/엔진 코드 분리(code-splitting)가 필요 — **출시 후 개선 후보**.

## 6. 출시 전 반드시 사람이 확인해야 할 항목
1. `docs/RC1_MOBILE_QA_CHECKLIST.md`를 **실제 모바일 기기**에서 전 항목 수행.
2. 키즈노트/카카오톡/메모장 **붙여넣기 형식**이 깨지지 않는지 실제 확인.
3. 구글 로그인/드라이브 백업·복원이 **실 기기 + 실 구글 계정**에서 동작하는지 확인.
4. 관리자 최초 비밀번호 설정 흐름이 운영 배포본에서 실제로 동작하는지 확인.
5. 일반 사용자 화면에 관리자/검수 정보가 보이지 않는지 눈으로 재확인.

## 7. 출시 후 개선 예정 항목
- 비밀번호 해시를 느린 KDF(PBKDF2 등)로 강화 검토.
- 관리자/검수 컴포넌트 lazy-load(code-splitting)로 번들에서 내부 토큰 분리.
- 기존 평문 계정 일괄 전환 수단(로그인 의존 제거) 검토.
- 검수 데이터 IndexedDB 이전(용량 한도 대비).
- 관찰일지 modular 전환(엄격 기준 충족 후 수동 승인).

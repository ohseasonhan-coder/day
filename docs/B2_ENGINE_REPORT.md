# 교사 기록 특화 언어 생성 엔진 2.0 검증 보고서

## 범위

- 외부 API, 외부 서버, 모델 다운로드 없이 브라우저 규칙만 사용한다.
- B2는 일반 사용자 기본 안전 엔진으로 유지한다. B3는 별도 `sw_b3_case_engine_enabled` flag로 분리한다.
- 7B와 WebLLM 경로, 서식 및 문서 유형은 변경하지 않았다.
- 내부 품질 점수는 실제 교사 사용성 지표가 아니다. 교사 검토 데이터는 별도로 누적한다.

## 구조

`입력 -> 증거 사실 카드 -> 조합 기반 테마 판정 -> 섹션 계획 -> 섹션별 후보 생성 -> 후보 점수화 -> 안전 재렌더링 -> B2 audit -> 기존 B fallback`

각 사실에는 `fact_n` ID와 입력 근거가 붙는다. 선택된 관찰내용, 배움 읽기, 지원 계획은 각각 `sectionEvidence`로 fact ID를 가진다. 테마와 지원 행동도 선택된 근거 ID를 유지한다.

## 후보 선택

- 관찰내용 후보: 기존 규칙 관찰문, 사실 순서문, 축약 사실문 중 기존 관찰문을 사실 보존 기준으로 고정한다.
- 배움 읽기 후보: 상황별 4~6개 골격을 생성한다.
- 지원 계획 후보: 테마에 허용된 지원 행동으로 3~4개 후보를 만든다.
- 금지 표현, 근거 누락, 과도한 길이, 섹션 중복, 희박 입력 과장을 감점 또는 탈락 처리한다.
- 동점은 입력 해시로 결정하므로 동일 입력은 항상 같은 결과를 낸다.
- 로컬 검토 데이터의 골격별 선택 이력은 작은 가중치로만 반영한다. 원문, 이름, 생성 전문은 저장하지 않는다.

## 정보 부족 처리

`교실에 있었다`, `놀았다`, `울었다`, `등원했다`처럼 의미 근거가 부족한 입력은 배움 읽기를 비운다. 지원 계획은 추가 관찰 안내로 제한하며, 재료와 상호작용을 묻는 선택형 보완 질문을 제안한다.

## 빠른 조정

- 더 짧게
- 더 객관적으로
- 더 따뜻하게
- 배움 읽기만 다시 정리
- 지원 계획을 더 구체적으로
- 직접 발화 강조
- 관찰 사실만 남기기

모든 조정은 기존 사실 카드와 계획을 다시 사용하며 새 의미를 추가하지 않는다.

## 개선 사례

1. `미끄럼틀 순서 잘기다렷다가 탐`에서 오타가 있어도 차례·순서 테마와 구체적 순환 놀이 지원을 선택했다.
2. `천둥소리에 놀라 귀를 막았다`에서 회복을 창작하지 않고 관찰된 감정 표현만 다뤘다.
3. 역할을 나눈 기록에서 역할 소품을 더하는 지원 계획으로 관찰 흐름을 연결했다.
4. 부정 감정 단독 기록에서 안정·진정·극복을 생성하지 않았다.
5. 직접 발화가 있는 기록에서 관찰내용의 발화를 그대로 보존했다.

## 보수 처리가 더 안전한 사례

1. `오늘 등원했다` -> 배움 읽기 생략, 추가 관찰 안내.
2. `교실에 있었다` -> 배움 읽기 생략, 사용 자료와 상호작용 질문.
3. `오전 자유놀이를 했다` -> 발달 의미를 만들지 않고 추가 관찰 대기.
4. `울었다` -> 회복이나 감정 조절 능력을 추정하지 않음.
5. 테마 근거가 없는 짧은 활동명 -> 일반 발달 문장 대신 추가 사실 확인.

## 남은 한계

- 은유적 발화는 발화를 보존할 수 있지만 은유의 의도와 의미 깊이는 규칙만으로 안전하게 해석하기 어렵다.
- 긴 복합 서사는 여러 사실의 중요도를 교사 관점으로 완전히 정렬하기 어렵다.
- 오타 교정은 판정용 정규화에만 적용하며 관찰 원문 자체의 의미를 임의로 고치지 않는다.
- 선택된 4개 골격의 실제 자연스러움은 교사 검토 표본으로 확인해야 한다.
- 내부 점수와 교사의 `그대로 사용 가능` 비율이 일치하는지는 아직 검증되지 않았다.

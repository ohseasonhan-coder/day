# 베타 롤백 / 데이터 복구 계획

> 베타 중 Blocker 발생 시 빠르게 안정 상태로 되돌리기 위한 절차입니다.
> 현재 운영 main: `33093dc` · 직전: `9b34075` · 그 이전: `69511d5`.

## 1. Vercel 이전 배포로 롤백 (앱 코드)
가장 빠른 방법(코드 변경 없이 배포만 되돌림):
1. Vercel 대시보드 → 프로젝트(day) → **Deployments**.
2. 직전 정상 배포(예: `9b34075`) 항목의 ⋯ 메뉴 → **Promote to Production**(또는 Rollback).
3. 운영 URL이 이전 배포로 즉시 전환되는지 확인.

Git으로 되돌리는 경우(다음 배포부터 반영):
```bash
git checkout main
git revert --no-edit <문제커밋>      # 이력 보존(권장)
git push origin main                  # Vercel 재배포 트리거
```
> `git reset --hard`로 main을 강제 이동하는 force-push는 지양(이력 손상·협업 위험). 꼭 필요하면 별도 승인 후 진행.

## 2. main 직전 커밋 확인
```bash
git fetch origin main
git log --oneline -5 origin/main      # 최근 커밋 목록
git show --stat <커밋>                # 변경 파일 확인
```
- 현재: `33093dc`(베타 QA 문서) ← `9b34075`(동기화/용어) ← `69511d5`(RC1 PR 초안).
- "직전 안정 배포"는 보통 `9b34075`(기능 변경 마지막 지점).

## 3. Google Drive 백업 파일로 복원 (사용자 데이터)
- 사용자 본인 Drive의 `saemwork_backup.json`이 데이터 원본.
- 앱: 설정 → 백업/복구 → **드라이브에서 가져오기**, 또는 🔁 기기 간 동기화 → **Drive에서 가져오기**.
- 파일 내보내기로 받은 JSON은 설정 → "데이터 가져오기"에서 **병합/덮어쓰기** 선택 복원.
- 복원은 **항상 로컬 안전 백업을 먼저 만든 뒤** 진행됨(아래 4).

## 4. 로컬 안전백업 확인
- 키: `sw_<userId>_safety_backup` (복원 직전 자동 1회 저장).
- 앱: 설정 → 🔁 기기 간 동기화 → **"방금 가져오기 전으로 되돌리기"**.
- 코드: `restoreLocalSafetyBackup()` (storage.js). 안전백업이 없으면 `{ ok:false }` 반환.

## 5. 동기화 충돌 시 대응
- 자동으로 덮어쓰지 않음. 사용자에게 3택 제시(이 기기 유지 / Drive 복원 / 안전보관 후 가져오기).
- 운영 안내: "충돌이 떠도 데이터가 지워지지 않습니다. ①~③ 중 하나를 고르세요. 잘못 골랐다면 '되돌리기'로 직전 상태로 복구할 수 있어요."

## 6. 사용자 안내 문구(공지용)
> "일시적인 문제로 일부 기능이 원활하지 않을 수 있습니다. 데이터는 기기와 (백업을 켠 경우) 본인 Google Drive에 안전하게 보관됩니다. 앱을 새로고침하거나 잠시 후 다시 시도해 주세요. 데이터가 이상해 보이면 **새로 입력하거나 덮어쓰지 마시고** 운영자에게 알려주세요."

## 7. 데이터 손상 의심 시 즉시 할 일
1. **추가 입력/덮어쓰기/동기화 중단** (손상 확산 방지).
2. 해당 기기에서 설정 → 🔁 동기화 → **되돌리기(안전 백업)** 시도.
3. 안전백업이 없으면 Drive `saemwork_backup.json`(가장 최근 정상본)으로 복원.
4. 운영자에게 증상·기기·시각 공유(개인정보 제외).
5. 코드 원인 의심 시 Vercel을 직전 정상 배포로 롤백(1) 후 원인 분석.
6. 원인/조치를 `BETA_DEVICE_QA_RESULT.md` 이슈 표에 기록.

# 기기 간 동기화 정책 (1차)

> 같은 사용자 계정으로 PC와 모바일에서 기록을 이어 쓰기 위한 "안전한 백업/복원 기반 동기화" 정책입니다.
> 실시간 동기화가 아니며, 외부 서버 없이 사용자 본인의 Google Drive만 사용합니다.

## 1. 동기화 목적
- 같은 Google 계정으로 로그인한 **여러 기기(같은 사용자)** 사이에서 원아 기록·문서·설정을 이어 쓰기.
- PC에서 작성 → 모바일에서 가져오기, 모바일에서 수정 → PC에서 가져오기.
- **서로 다른 사용자 계정 간 공유는 지원하지 않습니다.**

## 2. 동기화 대상
- 원아(아동) 목록, 반(class)
- 오늘기록/관찰기록 데이터
- 생성 문서·문서함(documents)
- 사용자 설정(settings)
- 반복일정(routines), 원 양식(formTemplates)
- 자동화 상태/로그, 복사 이력, 피드백
- onboarding 완료 여부
- 일반 사용자용 엔진 설정(`engineSettings` — 문서유형별 legacy/modular 플래그만, 비민감)

## 3. 동기화 제외 대상 (백업·동기화에 절대 포함하지 않음)
- 엔진 검수 데이터(`engine_reviews`)
- fallback 로그(`engine_fallbacks`)
- 사용자 교정 학습(`user_corrections`)
- 검수 샘플, 관리자 리포트, 디버그성 데이터
- 임시 세션(`sw_session`), 비밀번호/비밀번호 해시·솔트(`password`/`passwordHash`/`passwordSalt`)
- Google access token 등 인증 민감값(메모리에만 존재, 저장 안 함)
- Drive 메타(`sw_drive_backup_meta`)

> 위 목록은 코드 상수 `SYNC_EXCLUDED_KEYS`(`src/utils/storage.js`)로 관리되며, 페이로드에는 키 이름조차 담지 않습니다.

## 4. Google Drive 저장 방식
- 권한: `drive.file` — 이 앱이 만든 파일만 접근(드라이브의 다른 파일은 보지 못함).
- 파일: 사용자 본인 드라이브의 `saemwork_backup.json` 1개를 덮어쓰기/생성.
- 통신: 브라우저 ↔ 사용자 Google Drive 직접 통신. **개발자/외부 서버를 거치지 않습니다.**
- 백업 페이로드에는 동기화 메타데이터가 포함됩니다:
  - `schemaVersion`, `version`(backupVersion), `syncVersion`, `appVersion`
  - `userId`, `deviceId`(랜덤·비개인정보), `deviceName`(사용자 지정/기본값)
  - `exportedAt`, `dataUpdatedAt`, `checksum`(변경 감지용 경량 해시)

## 5. 충돌 처리 정책 (1차 — 안전 우선)
판정 근거: 로컬 `dataUpdatedAt`, 원격 `dataUpdatedAt`, 마지막 동기화 시점(`lastSyncedDataAt`).

| 상황 | 동작 |
|---|---|
| 원격 없음 | **push**(현재 데이터를 Drive에 백업) |
| Drive가 더 최신 + 로컬은 동기화 이후 그대로 | **pull**(Drive 데이터 가져오기) |
| 로컬이 더 최신 + Drive는 동기화 이후 그대로 | **push**(Drive에 백업) |
| 양쪽 모두 마지막 동기화 이후 변경 | **conflict** — 자동 덮어쓰기 금지, 사용자에게 선택 요청 |
| 시각 동일 | **in-sync**(할 일 없음) |

충돌 시 사용자 선택:
1. 이 기기 데이터 유지(Drive에 백업)
2. Drive 데이터로 복원
3. 현재 데이터 안전 보관 후 Drive 데이터 가져오기

**안전장치**
- 복원(pull) 전 현재 데이터를 **로컬 안전 백업**(`*_safety_backup`)으로 1회 보관 → "방금 가져오기 전으로 되돌리기" 가능.
- 가져오기 실패(잘못된 파일/네트워크 오류) 시 **기존 데이터를 그대로 유지**.
- 자동으로 원아/문서 데이터를 삭제하지 않음.

## 6. 자동 동기화(보수적)
- 사용자가 설정에서 **자동 백업을 켠 경우에만** 동작.
- 앱 시작 후 **1회만** 최신 상태 확인(세션당 1회). 원격이 명백히 최신이고 로컬이 그대로일 때만 자동 가져오기. 충돌/로컬 최신이면 **자동으로 데이터를 바꾸지 않고** 설정 화면에서 수동 선택.
- 데이터 변경 시 30초 디바운스 후 1회 업로드(기존 구조), Drive API 과호출 방지.
- 실패는 조용히 무시하지 않고 설정 화면에 상태 표시("동기화하지 못했어요. 인터넷 연결 또는 Google 로그인을 확인해주세요.").

## 7. 개인정보 보호 안내
- 원아 기록·문서·설정 등 개인정보는 **사용자 본인의 Google Drive에만** 저장되며 외부 서버로 전송되지 않습니다.
- 비밀번호/해시/세션/토큰 등 인증 민감값은 동기화 대상이 아닙니다.
- 공용 기기 주의: 사용 후 로그아웃하고 브라우저 저장 데이터를 삭제하세요. 이 앱은 기록을 기본적으로 기기에 저장합니다.

## 8. 남은 한계
- 실시간 동기화가 아니며, 항목 단위 자동 병합도 하지 않습니다(파일 단위 가져오기/내보내기 + 충돌 시 사용자 선택).
- 충돌 시 자동 병합 대신 한쪽을 선택하므로, 양쪽에서 동시에 많이 작업한 경우 한쪽 변경은 안전 백업에만 남을 수 있습니다.
- `checksum`은 변경 감지용 경량 해시이며 암호학적 무결성 보증은 아닙니다.
- 사진 등 IndexedDB 대용량 데이터는 이번 동기화 대상에 포함되지 않습니다.
- 충돌 판정은 `dataUpdatedAt`(로컬 자료 변경 시각) 기준이며, 기기 시계가 크게 어긋나면 판정이 부정확할 수 있습니다.

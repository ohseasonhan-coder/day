# 기기 간 동기화 — 실사용 QA 체크리스트

> 사람이 **실기기 + 실 Google 계정**으로 수행하는 PC↔모바일 동기화 검증 시트입니다.
> 테스트용 데이터만 사용하고 **실제 원아 개인정보는 넣지 마세요.**
> 동기화 로직/제외/충돌 판정/안전백업은 자동 테스트(`deviceSync.test.js` 17건)와 코드 점검으로 이미 검증됨 — 이 문서는 **실 Drive 왕복 클릭 검증** 전용입니다.

## 0. 환경 기록
- PC: 브라우저 ____________ / 배포 URL ____________
- 모바일: 기기 ____________ / 브라우저 ____________
- 테스트 Google 계정: ____________ (실 원아정보 금지)
- 테스트 날짜: ____________ / 담당자: ____________
- 사전 준비: 설정 → 백업/복구에서 구글 클라이언트 ID 설정 + **자동 백업 ON**(자동 동기화 동작 조건)

## A. PC → 모바일 이어쓰기
- [ ] PC에서 테스트 계정(Google) 로그인
- [ ] 원아 1명 등록(예: "테스트원아")
- [ ] 오늘기록 입력 → 문장 생성
- [ ] 문서 저장(문서함에 보임)
- [ ] 설정 → 🔁 기기 간 동기화 → **지금 백업하기** 성공 메시지
- [ ] 모바일에서 같은 Google 계정 로그인
- [ ] 설정 → 🔁 기기 간 동기화 → **Drive 최신 데이터 확인** → "가져오면 최신으로 맞춰져요" 안내
- [ ] **Drive에서 가져오기** → 성공
- [ ] 모바일에 원아/오늘기록/문서가 그대로 보임

## B. 모바일 → PC 이어쓰기
- [ ] 모바일에서 기록 1건 추가 → 문서 저장
- [ ] 설정 → 🔁 기기 간 동기화 → **지금 백업하기** 성공
- [ ] PC에서 설정 → 🔁 기기 간 동기화 → **Drive 최신 데이터 확인**
- [ ] **Drive에서 가져오기** → 성공
- [ ] PC에 모바일에서 추가한 기록/문서가 보임

## C. 충돌 처리
- [ ] PC·모바일 양쪽에서 한 번 동기화로 같은 상태를 맞춤(기준점)
- [ ] PC에서 기록 A 추가(백업하지 않음)
- [ ] 모바일에서 기록 B 추가 → **지금 백업하기**(Drive가 B로 갱신됨)
- [ ] PC에서 **Drive 최신 데이터 확인** → **충돌 안내**가 표시되고 자동으로 덮어쓰지 않음
- [ ] 충돌 3택이 보임:
  - [ ] ① 이 기기 데이터 유지(Drive에 백업) → 선택 시 PC의 A가 Drive에 올라감 (결과 확인: ____________)
  - [ ] ② Drive 데이터로 복원 → 선택 시 PC가 B로 맞춰짐 (결과 확인: ____________)
  - [ ] ③ 현재 데이터 안전 보관 후 Drive 데이터 가져오기 → PC가 B로 맞춰지고, A는 안전백업에 남음 (결과 확인: ____________)
- [ ] (③ 선택 후) "방금 가져오기 전으로 되돌리기"로 A 복구 가능

## D. 안전백업 / 복원 실패
- [ ] **Drive에서 가져오기** 직전 현재 로컬 데이터가 안전 백업으로 보관됨(되돌리기 버튼 활성)
- [ ] "방금 가져오기 전으로 되돌리기" 클릭 → 직전 데이터로 복구
- [ ] (오프라인/로그아웃 상태에서) 가져오기 시도 → 실패 안내가 뜨고 **기존 데이터가 그대로 유지**됨
   - 안내 예: "가져오지 못했어요. … 기존 데이터는 그대로 유지됐어요."

## E. 제외 데이터 확인 (백업 파일 점검)
> 설정 → 백업/복구 → **데이터 내보내기**(JSON)로 받은 파일, 또는 Drive의 `saemwork_backup.json`을 텍스트로 열어 확인.
- [ ] `engine_reviews` / `engine_fallbacks` / `user_corrections` 문자열이 없음
- [ ] `password` / `passwordHash` / `passwordSalt` 가 없음
- [ ] `accessToken` / 세션(`sw_session`) 값이 없음
- [ ] 원아·기록·문서·설정·`onboardingDone`·`engineSettings`(플래그)는 포함됨
- [ ] 메타(`deviceId`·`deviceName`·`dataUpdatedAt`·`schemaVersion`·`checksum`)가 포함됨

## F. 용어 확인
- [ ] 설정 메뉴/관리 화면 제목이 **원아 관리**
- [ ] 빈 상태가 **등록된 원아가 없어요**, 버튼 **원아 추가하기**, 검색 **원아 이름으로 검색**
- [ ] 폼 라벨이 **원아 선택**(투약/사고/상담)
- [ ] 사용자 화면 어디에도 **아이 관리/아이관리/전체 아이** 같은 관리 문구가 없음
- [ ] 생성된 부모 전달 문장에서는 자연스러운 "아이" 표현이 유지됨(문체 변경 없음)
- [ ] 일반 사용자 화면에 관리자/검수 정보(엔진명·점수·fallback 사유·modular/legacy)가 보이지 않음

## 자동 검증으로 이미 통과한 항목 (참고)
| 항목 | 검증 방식 | 상태 |
|---|---|---|
| 자동 동기화는 자동 백업 ON일 때만 | `App.js` `if(!settings.driveAutoBackup) return` | ✅ 코드 |
| 앱 시작 세션당 1회 확인 | `sessionStorage('sw_autosync_done')` | ✅ 코드 |
| 원격 명확 최신+로컬 그대로일 때만 자동 가져오기 | `autoSyncOnStart` action==='pull'만 적용 | ✅ 코드 |
| 충돌 시 자동 덮어쓰기 없음 | `decideSyncAction` both-changed→conflict | ✅ 테스트 |
| 복원 전 안전백업 생성 | `pullFromDrive` saveLocalSafetyBackup 선행 | ✅ 테스트 |
| 복원 실패 시 데이터 유지 | 잘못된 JSON pull → ok:false, 데이터 동일 | ✅ 테스트 |
| 제외 데이터 미포함 | payload에 reviews/fallbacks/corrections/세션/비번 없음 | ✅ 테스트 |
| deviceId 랜덤·유지 / deviceName 수정 | `getDeviceId`/`setDeviceName` | ✅ 테스트/코드 |
| 관리자/검수 비노출 | `adminExposure.test.js` | ✅ 테스트 |
| 원아 용어 통일 | `studentWording.test.js` | ✅ 테스트 |

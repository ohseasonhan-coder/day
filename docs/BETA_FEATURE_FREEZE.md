# 베타 기능 동결 선언 (Feature Freeze)

> 기준 커밋: `33093dc` (origin/main 동일) · 발효: 베타 시작 시점부터 베타 종료까지.
> 목적: 베타 기간 동안 앱을 **안정 상태로 고정**하고, 변경을 안전한 범위로만 제한.

## 1. 새 기능 추가 중단
- 베타 기간에는 **새 기능을 추가하지 않습니다.** 기능 아이디어는 "Idea"로 기록만 하고 베타 후 검토.

## 2. 허용되는 변경 (베타 중 가능)
- 버그 수정(Blocker/Major)
- 오타·문구 개선
- 데이터 손상 방지/복구 관련 수정
- 보안 수정
- 안내 문구·접근성 개선

## 3. 금지되는 변경 (베타 중 불가)
- AI 생성 로직·modular/legacy·fallback·문장 엔진 **대규모 변경**
- 데이터 구조(localStorage 키/백업 payload) **대규모 변경**
- 메뉴 구조·라우트 **대규모 변경**
- 외부 서버·외부 LLM API 추가

> 불가피하게 데이터 구조를 건드려야 하는 손상 방지 수정은 **추가 필드(하위호환)** 범위로만, 마이그레이션과 함께 진행.

## 4. 이슈 등급 기준
| 등급 | 정의 | 처리 |
|---|---|---|
| **Blocker** | 데이터 손상·로그인 불가·앱 크래시·개인정보 노출 | **즉시 수정**(필요 시 롤백 — `BETA_ROLLBACK_PLAN.md`) |
| **Major** | 핵심 흐름 일부 실패(복사·저장·동기화 등), 우회 가능하나 불편 큼 | **베타 중 수정** |
| **Minor** | 사소한 UI/문구/엣지 케이스 | **베타 후 개선** |
| **Idea** | 새 기능 제안·개선 아이디어 | **향후 기능 후보**로 기록 |

## 5. 변경 절차(베타 중)
1. 이슈 접수 → 등급 분류(위 표).
2. Blocker/Major만 작업. 작업 전 `git`에서 분기, 테스트/빌드 통과 확인.
3. main FF 병합 → Vercel 자동 배포 → `BETA_DEVICE_QA_RESULT.md`에 재검증 기록.
4. 변경 시 `saem2026`/`dev-master` 0건·소스맵 없음·동기화 제외 데이터 유지 재확인.

## 6. 동결 해제
- 베타 종료 + 회고 후 해제. 누적된 Minor/Idea를 정식 백로그로 전환.

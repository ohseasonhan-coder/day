# 개인 PC 7B 서버 실검증 보고서

- 검증일: 2026-07-03
- 범위: `private-server-7b` 연결, 오류 fallback, 비식별 합성 사례 20건 품질·속도 검증
- 서식 관리 MVP: 변경·확장하지 않음

## 1. 실제 실행 모델과 설치 방식

- 런타임: Ollama `0.31.1` Windows AMD64 ZIP
- 설치 방식: 시스템 설치가 아닌 `%TEMP%/saemwork-ollama` 포터블 실행
- 모델: `qwen2.5:7b-instruct`
- 모델 파일 크기: 약 4.7GB
- API: `http://localhost:11434/v1`
- 확인 경로: `/v1/models`, `/v1/chat/completions`
- 브라우저 허용 origin: localhost 개발 주소와 쌤워크 배포 주소

Ollama/LM Studio가 없는 PC에서 공식 Ollama ZIP을 내려받아 서버를 직접 실행했고, 모델 pull부터 OpenAI 호환 응답까지 실제 확인했다. 사용자는 앱 브라우저에서 모델을 다운로드하지 않으며, 모델은 서버 PC에만 존재한다.

## 2. 검증 PC 사양과 메모리

- PC: Samsung 550XED
- 시스템 RAM: 15.7GB
- GPU: Intel Iris Xe Graphics
- 표시 전용 VRAM: 1GB
- Ollama 실행 장치: `100% CPU`
- 모델 로드 크기(`ollama ps`): 약 5.1GB
- `llama-server` working set: 약 4.7~4.8GB
- `llama-server` private memory: 약 4.93GB

이 PC에서는 외장 GPU 가속 없이 CPU 추론으로 동작했다. VRAM 사용량을 별도 NVIDIA 도구로 측정할 수 없었으며 Ollama는 CPU 100%로 보고했다.

## 3. 최종 설정

- temperature: `0.2`
- max tokens: `160`
- timeout: `75초`
- 네트워크/5xx 재시도: 최대 1회
- timeout 재시도: 없음
- JSON 파싱 오류: 동일 사실카드로 1회 재생성
- 출력: `learningReading`, `supportAndNextPlan` JSON 두 필드
- 관찰내용: 규칙 엔진 결과를 그대로 유지
- C안 검수 실패: 즉시 B안 반환

timeout을 재시도하지 않는 이유는 Ollama가 이전 생성 작업을 계속 수행해 요청 큐가 길어질 수 있기 때문이다.

## 4. 비식별 합성 사례 20건 결과

최종 실행 결과:

| 항목 | 결과 |
|---|---:|
| 전체 사례 | 20건 |
| 자동 audit 통과 C안 | 17건 |
| B안 fallback | 3건 |
| 자동 audit 통과율 | 85% |
| 평균 응답시간 | 27.403초 |
| p95 응답시간 | 36.277초 |
| 자동 복붙 점수 C안 우위 | 0건 |
| 자동 복붙 점수 동률 | 20건 |
| 자동 복붙 점수 B안 우위 | 0건 |

최종 fallback 사례:

- 팽이 놀이: 반복 표현(`생각을`) 감지
- 감정 표현: 외국 문자와 문장 미완결 감지
- 울음·속상함: 부정적·진단성 표현 감지

자동 점수는 형식과 안전성을 중심으로 보므로, C안의 실제 자연스러움 우위를 충분히 판별하지 못했다. 사람 검토에서는 자동 audit 통과안 중에도 관찰내용 반복과 일반적인 지원 문장이 남았다.

## 5. B안 대비 사례

### C안에서 상대적으로 구체화된 사례

- 자연탐구: 개미의 줄 이동을 관찰하고 규칙성을 인식하는 방향으로 구체화했다.
- 나뭇잎 관찰: 크기 비교 행동과 다음 비교 자료 지원을 연결했다.
- 거부 표현: `안 할래요`를 자기 의견 표현과 연결했다.

다만 위 사례도 문체와 사실 해석을 교사가 다시 확인해야 하며, B안보다 명확히 우수하다고 판정할 충분한 표본은 확보하지 못했다.

### B안이 더 안전했던 사례

- 감정 표현: C안에 외국 문자가 섞여 audit가 차단하고 B안으로 전환했다.
- 울음·속상함: C안의 부정적·진단성 표현을 차단하고 B안으로 전환했다.
- 신체놀이: C안이 입력에 없는 `자신감`, `더 큰 평균대`를 제안한 사례가 있어 B안이 더 보수적이었다.
- 물감 탐색: C안이 입력에 없는 `칠판`을 제안한 사례가 있어 B안이 더 안전했다.
- 명령조 수정: C안이 관찰 사실을 반복하고 이미 배웠다고 단정해 B안의 지원 문장이 더 적절했다.

## 6. 실패·fallback 검증

확인한 시나리오:

- 서버 주소 미설정: 규칙 B안
- 서버 미실행/연결 실패: 규칙 B안
- timeout: 재시도 없이 규칙 B안
- 일시적 HTTP 5xx: 1회 재시도, 실패 시 규칙 B안
- JSON 없음/파싱 오류: 1회 재생성 후 규칙 B안
- 빈 필드/지나치게 짧은 출력: 규칙 B안
- 입력에 없는 또래·발화: audit 차단 후 규칙 B안
- 금지 표현·반복·외국 문자·문장 미완결: audit 차단 후 규칙 B안
- 교사 지원 과거형 단정: audit 차단 후 규칙 B안

기록 작성의 기본 결과는 먼저 규칙 엔진에서 준비되므로 7B 실패가 기록 저장 자체를 막지 않는다.

## 7. 남은 품질 문제

1. 관찰 행동을 배움 읽기에 그대로 반복하는 경향
2. `대화 기회를 제공한다` 같은 일반 지원 문장 반복
3. 입력에 없는 재료나 자신감·능력 같은 의미 확장
4. `배웠습니다`, `도움이 될 것입니다` 등 교사 문서와 맞지 않는 문체
5. CPU PC 평균 약 27초로 긴 응답시간
6. 자동 audit 점수와 실제 교사 자연스러움 판단 사이의 차이
7. 20건 중 C안이 B안보다 명백히 우수하다고 확정할 사례가 부족함

## 8. 승격 판단

### 일반 사용자 기능 승격

**보류.**

- 실제 서버 실행과 연결은 성공했다.
- 오류 시 B안 fallback도 작동한다.
- 그러나 C안이 B안보다 자연스럽고 개별적이라는 완료 기준을 충족하지 못했다.
- CPU 환경의 평균 27초는 동기 UI로 제공하기에 길다.

현재는 관리자·검수자 전용 실험 기능으로 유지해야 한다. 다음 검증은 외장 GPU가 있는 서버 PC에서 동일 20건을 다시 실행하고, 실제 비식별 교사 기록 30~50건을 A/B/C 블라인드 검토하는 방식이 적절하다.

### 서식 자동 채우기 단계 전환

**보류.**

7B가 B안보다 실제로 낫다는 근거가 아직 없으므로 서식 자동 채우기 확장으로 넘어가지 않는다. 서식 관리 MVP는 현재 상태로 동결한다.
